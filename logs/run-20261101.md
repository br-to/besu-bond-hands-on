# 通し実行ログ 2026-11-01

README の手順を、この Cloud Agent VM 上で Docker つき Besu クイックスタートに対して実行した結果です。値は捏造していません。

## 環境

- Ubuntu 24.04.5 LTS、x86_64
- 当初 `docker` コマンドは未導入だったため、検証用に `apt` の `docker.io` と `docker-compose-v2` を入れて `dockerd` を手動起動した
- Docker 29.1.3、Docker Compose 2.40.3
- Node v22.23.4
- Foundry forge 1.8.7
- `@consensys-software/besu-dev-quickstart@0.2.2`（生成 `.env` は `BESU_VERSION=26.2.0`）
- Besu `besu/v26.2.0/linux-x86_64/openjdk-java-25`

PID 1 が systemd ではないため `service docker start` は使えず、`sudo dockerd` でデーモンを上げた。

## ネットワーク起動

```bash
npx -y @consensys-software/besu-dev-quickstart@0.2.2 --networkType private \
  --outputPath ./besu-test-network --otel false --chainlens true
cd besu-test-network
TERM=xterm ./run.sh
```

`run.sh` は約 21 秒で完了し、validator 4 + rpcnode + 監視 + Chainlens が起動した。

記事と同じく、ホストに `iptables-legacy` の `FORWARD` ポリシー `DROP` があり、起動直後は `net_peerCount=0x0` / `eth_blockNumber=0x0` だった。次を入れてから peers が `0x4` になり、ブロック生成が始まった。

```bash
sudo iptables-legacy -I DOCKER-USER -s 172.16.239.0/24 -d 172.16.239.0/24 -j ACCEPT
```
